Kapan Lu Wajib Pakai Next.js, dan Kapan Lu Mendingan Jangan?

Bukan sekadar perbandingan teori. Kami bedah arsitektur nyata di balik website raksasa dunia: dari TikTok, Notion, ChatGPT (yang pakai Next.js) sampai YouTube, GitHub, Figma, Linear (yang sengaja menolak Next.js).

PRO-NEXT.JS

Gunakan Next.js Kalau:

  • ✦SEO & Social Sharing adalah Nyawa Bisnis: E-commerce, portal berita, landing page publik butuh pre-rendered HTML + dynamic OpenGraph tags instan.
  • ✦Skala Katalog Jutaan Halaman: Butuh Incremental Static Regeneration (ISR) untuk cache edge tanpa rebuild berjam-jam.
  • ✦Fullstack Satu Bahasa: Satu repo TypeScript dari front-end UI, Server Components (RSC), sampai Edge Route Handlers.
NON-NEXT.JS BETTER

JANGAN Pakai Next.js Kalau:

  • ✕Heavy Canvas / WebGL Engine (Contoh: Figma): DOM tree dan SSR tidak berguna untuk 60 FPS graphics loop biner WebAssembly.
  • ✕Local-First Instant App (Contoh: Linear): Semua data di-cache di client SQLite/IndexedDB, roundtrip server SSR justru bikin lag.
  • ✕Massive High-Throughput Read Cache (Contoh: Wikipedia, GitHub): SSR Rails / PHP Varnish edge jauh lebih hemat resource daripada ribuan Node.js SSR runtime processes.

Arsitektur & Trade-Off Matrix

Head-to-Head: Next.js vs SPA vs MPA Tradisional

Setiap pilihan arsitektur adalah barter (trade-off). Tidak ada framework yang unggul di semua sektor. Pilihlah berdasarkan constraint bisnis lu.

Next.js 15 (App Router)Hybrid SSR/RSC

HTML dan OpenGraph tags di-render di server/edge sebelum dikirim ke client. Search bot dan chat preview bots (WhatsApp, Twitter, FB) langsung baca tag lengkap.

Kelebihan Arsitektur:
  • 100% crawlable oleh bot tanpa Javascript execution
  • Dynamic OpenGraph preview gambar per halaman
  • Sitemap & metadata built-in
Kekurangan / Trade-off:
  • Butuh compute server/edge (Vercel/Node/Docker)
Verdict Principal Architect:

Kemenangan mutlak untuk e-commerce, portal berita, dan website publik.

Pure Client SPA (Vite)Client-Side Only

Server cuma kirim satu file HTML kosong `div id='root' /div` + bundle JS besar. Browser client baru fetch data dan render DOM setelah JS selesai dieksekusi.

Kelebihan Arsitektur:
  • Bisa di-host gratis di object storage statis (S3, Cloudflare Pages, GitHub Pages)
Kekurangan / Trade-off:
  • Bot chat (WA/Telegram) gak dapet preview OG
  • Googlebot butuh antrean 'second wave indexing' untuk eksekusi JS
Verdict Principal Architect:

Bencana untuk public content marketing; oke hanya untuk dashboard private di balik login.

Traditional MPARails / Laravel / PHP

Server (Laravel, Rails, Django, Go) merender full HTML per URL request dari database secara langsung.

Kelebihan Arsitektur:
  • SEO sempurna secara native
  • Nol overhead framework JS client
Kekurangan / Trade-off:
  • Navigasi antar halaman memicu reload browser penuh (full-page flash/reload) kecuali pakai Turbo/HTMX
Verdict Principal Architect:

Sangat solid untuk konten & dokumentasi.

Perbedaan Kode: Next.js vs SPA Tradisional

Lihat bagaimana mental model kode berubah: hilangnya boilerplate `useEffect`, hilangnya loading state client yang berlebihan, dan simplifikasi arsitektur data.

Next.js App RouterServer-First
// app/products/[slug]/page.tsx (React Server Component)
import { db } from "@/lib/db";
import type { Metadata } from "next";

// 1. Dynamic SEO Metadata di server (Langsung dibaca Googlebot)
export async function generateMetadata({ params }): Promise<Metadata> {
  const product = await db.products.findUnique({ where: { slug: params.slug } });
  return {
    title: product.name,
    openGraph: { images: [product.ogImage] }
  };
}

// 2. Data Fetching murni di server (0 KB bundle JS terkirim ke client!)
export default async function ProductPage({ params }) {
  const product = await db.products.findUnique({ where: { slug: params.slug } });
  return (
    <article className="p-8">
      <h1>{product.name}</h1>
      <p>Harga: {product.price}</p>
    </article>
  );
}
Pure React SPA (Vite)Client-First
// src/pages/ProductDetail.tsx (Vite / React SPA)
import React, { useEffect, useState } from "react";
import { useParams } from "react-router-dom";
import { Helmet } from "react-helmet-async"; // Sering telat di-crawl bot!

export default function ProductDetail() {
  const { slug } = useParams();
  const [product, setProduct] = useState(null);
  const [loading, setLoading] = useState(true);

  // Butuh fetch client-side: Bikin "White Screen" & Waterfall loading
  useEffect(() => {
    fetch(`/api/products/${slug}`)
      .then((res) => res.json())
      .then((data) => {
        setProduct(data);
        setLoading(false);
      });
  }, [slug]);

  if (loading) return <div>Loading spinner...</div>;

  return (
    <article className="p-8">
      <Helmet>
        <title>{product.name}</title>
      </Helmet>
      <h1>{product.name}</h1>
      <p>Harga: {product.price}</p>
    </article>
  );
}
